# 路线图

候选功能，按价值和实现成本分成三个梯队。这里只记打算做什么、为什么做；做完的功能写进 [architecture.md](architecture.md)，再从本文删掉。

调研日期：2026-11-04。

## 现状里的缺口

- `internal/engine` 只编译了 `local`、`s3`、`smb` 三个后端。
- Windows 上 `launchagent.Register` 返回 `errors.ErrUnsupported`，定时任务只在应用打开时运行。

## 第一梯队：缺口明显、成本不高

### 1. Windows 后台调度

给 Windows 实现一个 `service.Registrar`，用任务计划程序（Task Scheduler XML 加 `schtasks`），让应用退出后定时任务照常运行，行为与 macOS 一致。

- 同样要先经过 `background` 同意，被拒绝时退回由窗口运行。

## 第二梯队：扩大适用范围

### 2. 更多存储类型

- WebDAV（群晖、Nextcloud、坚果云）和 SFTP：在 engine 里加空白导入，主要工作是表单、校验和连接错误分类。
- 网盘（Google Drive、OneDrive、Dropbox）要做 OAuth 授权和令牌刷新，成本高一档，排在 WebDAV 和 SFTP 之后。

### 3. 客户端加密

用 rclone 的 `crypt` 套在任意存储外面，文件在本机加密后再上传。加密密码通过 `service.Secrets` 存进系统凭据存储。忘记密码数据就找不回来，界面必须讲清楚。

### 4. S3 存储类别

可选标准、低频、归档（Glacier、Deep Archive、OSS 归档），冷备份能省很多钱。归档类别读回要先解冻，恢复时需要说明。

### 5. 反向恢复

在任务上提供「从目标恢复到…」：一次性把目标 copy 回本机文件夹，文件夹由用户选择，默认不覆盖来源。现在要恢复只能手动新建一个反向任务。

### 6. 完整性校验

用 rclone 的 `check` 对比两端，可以手动或按计划运行，结果记进历史，作为一种运行类型。

## 第三梯队：更贴合笔记本的使用场景

### 7. 运行条件

只在接电源时运行、只在指定 Wi‑Fi 下运行、开热点或用蜂窝网络时跳过。不满足条件时推迟到满足后再跑，而不是记为失败。

### 8. 事件触发

- 外接硬盘插上时运行（监听卷挂载）。
- 文件夹变化后延迟运行（fsnotify 加防抖）。只有窗口进程能监听，后台调度进程做不到，需要设计两者如何配合。

### 9. 分时段限速

白天限速、夜里不限（rclone 原生支持 bwlimit 时间表），也可以为单个任务设限速。

### 10. 目标空间显示

用 rclone 的 `about` 在存储页显示已用和剩余空间，NAS 快满时提醒。不是所有后端都支持，不支持时不显示。

## 暂不建议

- **双向同步（bisync）**：冲突处理复杂、出错代价大，和现在「安全优先」的定位不搭。
- **命令行**：应用不提供面向用户的命令行（见 architecture.md「设置」）。真要做自动化，更合适的是 macOS 快捷指令（App Intents）或 URL scheme。

## 建议顺序

1. Windows 后台调度（1）。
2. WebDAV 和 SFTP（2），再看第二、三梯队的其他项。
