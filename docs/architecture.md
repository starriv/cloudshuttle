# 架构

云梭是一个 Go 模块、一个可执行文件：MyGo 桌面应用，窗口绘制原生界面，rclone 编译在内。它以两种进程运行：窗口；以及系统按定时任务的时间启动的后台调度进程（同一个可执行文件加 `--scheduler`），见「定时任务」。

```
cmd/cloudshuttle   入口：窗口、托盘、钥匙串适配、系统通知、灵动岛窗口（macOS）、后台调度进程
internal/view      原生界面（ui 包）：页面、对话框
internal/island    灵动岛：刘海处显示运行进度的胶囊的状态与视图
internal/icons     图标（Tabler outline SVG）
internal/format    大小与时长的格式化
internal/service   核心：存储、任务、运行、定时调度（两个进程共用）
internal/launchagent 向系统登记定时任务：macOS 上是 launchd 的 launch agent
internal/updates   自动更新：何时检查、下载，等任务结束后重启；下载和替换交给 MyGo
internal/engine    以库的方式调用 rclone：构建远端、复制、同步、连接检查、列出 SMB 共享和文件夹
internal/discovery 用 Bonjour（mDNS）查找局域网中的 SMB 服务器
internal/store     SQLite（modernc.org/sqlite，纯 Go）
internal/icloud    iCloud Drive 中应用自己的文件夹（macOS）
internal/seal      用密码加密、解密备份文件（Argon2id + XChaCha20-Poly1305）
internal/domain    模型、校验、错误；不依赖上面任何包
locales            文案目录（en、zh-Hans）和生成的访问函数
resources          应用图标与单色品牌标志
design/brand       品牌矢量源稿、分层 Icon Composer 文档及素材导出脚本
```

依赖只能自上而下：`view` 和 `island` 调用 `service`，共用 `icons` 和 `format`；`service` 调用 `store`、`engine`、`discovery`、`icloud`、`seal` 和 `domain`；`launchagent` 只依赖 `domain`，由 `cmd` 创建后作为 `service.Registrar` 交给 `service`；`updates` 不依赖应用的其他包，由 `cmd` 创建并交给 `view`（`App.SetUpdater`）；没有包引用 `view` 或 `cmd`。

## 模型

- **存储（Storage）**：按种类（`Kind`）分两种，只填自己那一种的字段。新建时名称可以留空：S3 用所选 Provider 的名字（例如 Amazon S3、Cloudflare R2、MinIO），SMB 用服务器的主机名（没有主机时用 SMB），重名时依次加 “ (2)”“ (3)”。名称框用灰色占位符显示这个默认值；保存时仍为空才真正采用它。编辑已有存储不会改写名称。
  - `s3`：一个兼容 S3 的存储桶，包含服务商、Endpoint、区域、存储桶和 Access Key ID。Secret Access Key 存在系统凭据存储，键名为 `storage/<id>/secret-access-key`。
  - `smb`：一台 SMB 服务器的连接方式，只有主机、端口（默认 445）和用户名，不含共享：共享和其中的文件夹由任务选。新建时密码必填，用户名为 `guest`（访客访问）时除外；编辑时留空表示沿用。密码存在系统凭据存储，键名为 `storage/<id>/password`。没有密码时，连接测试和保存都直接报字段错误，不发请求。只用 NTLM 登录：rclone 的 Kerberos 要读环境变量和 `krb5.conf`，与「不读 rclone 环境」的原则冲突。`StorageInput.Normalize` 从粘贴的 `smb://host:port/share` 或 `\\host\share` 里取出主机和端口，忽略共享。
  - 两种密钥都通过 `service.Secrets` 接口存取；存储换种类时，旧种类的密钥随之删除。
- **任务（Task）**：来源和目标两个 `Location`（`StorageID` 为空表示本机文件夹，否则是存储里的路径：存储桶内的路径，或 SMB 服务器上以共享名开头的路径，如 `Documents/照片`，SMB 一端的路径不能为空。存储只管连接，同步哪里由任务决定，同一个存储可以给多个任务用；SMB 路径比较时不分大小写），方式（`copy` 从不删除；`sync` 会删除来源中没有的文件），计划（`domain.Schedule`，见「定时任务」），以及回收站保留天数（`TrashDays`：0 跟随设置，-1 关闭，正数是这个任务自己的天数；`Task.Trash` 结合设置得出实际天数，0 表示不进回收站），以及排除规则（`domain.Exclude`：一组 glob 和「跳过大于 N 字节的文件」，0 表示不限；新任务默认排除 `.DS_Store` 和 `Thumbs.db`，见「任务如何运行」）。设置里的「全局排除」默认开启，规则清单（`Settings.GlobalExcludes`，新数据库以开发依赖和构建目录 `domain.DevDependencyExcludes` 开头）可以在设置页查看和编辑，任务自己的规则之外再生效。
- **运行（Run）**：任务的一次执行，可以是手动、定时或试运行。记录当时的任务名、状态和 rclone 的统计数据，以及移进回收站的文件数和文件夹（`trashed`、`trash`）；被删除预检拦下时还记录原因码（`problem`），由界面翻译，以及会删除的文件（见「任务如何运行」）。

校验在 `domain` 中完成：`StorageInput.Validate` 和 `TaskInput.Validate` 返回 `domain.Problems`，每个出错字段一个错误码，由界面翻译成用户语言显示在字段旁边。

本地路径在保存时解析为真实路径，包括尚未创建的目标的已有父目录；悬空链接和无法解析的路径拒绝保存。取得传输锁后、真正执行前再校验一次，并使用该次解析的路径执行。

任务的目标在保存时另有一组检查，防止一次同步删掉不该删的东西：

- 路径里的任何一段都不能是 `..`（`CodeInvalidPath`），否则它指向的并不是它看起来的那个文件夹。
- sync 的本地目标不能是卷根（`/`、`C:\`、`\\server\share`，`CodeForbiddenDestination`）；`service` 还拒绝主文件夹、主文件夹的上级、应用自己的数据目录（及其上下级）和系统自己的文件夹（`/System`、`/Library`、`/Applications`、`/Users`、`/Volumes` 等）。copy 不受此限，因为它不删除。
- 两个任务不能写同一个目标：只要其中一个是 sync，目标相同或互相包含都拒绝（`CodeSharedDestination`），因为一个任务会把另一个放进去的文件当作多余的文件删掉。两个 copy 写同一个目标则允许。运行开始时检查本进程活动任务的目标冲突，冲突时以 `domain.ErrDestinationBusy` 拒绝；取得跨进程传输锁后，再检查与已保存任务的目标冲突。试运行不写入文件，免除目标冲突检查。

## 任务如何运行

1. `Service.Run` 写入一条 `running` 状态的运行记录并启动 goroutine；同一任务同时只能有一个运行（`ErrAlreadyActive`），无论它在窗口还是后台调度进程里运行。应用同一时间只传输一个任务，两个进程之间也是：其余的运行已经记录、在队列里等（`Active.Queued`，界面显示「等待运行」），轮到它才真正开始。
2. goroutine 解析两端位置，读取存储的密钥，然后调用 `engine.Run`。
3. `engine.Run` 在内存中构建 rclone 远端（`local`、`s3` 或 `smb` 后端）：后端选项默认值加上存储的配置，不读配置文件也不读环境变量；SMB 密码按 rclone 的要求在内存中混淆后传入。运行时使用的并发文件数、并发检查数、重试次数和带宽上限来自设置页，在运行开始时取一份快照。引擎将带宽上限设置到 rclone 的全局 token bucket，并在运行结束时清除；引擎内的运行互斥避免它被其他运行覆盖。
   - **删除预检**：sync（且不是试运行、不是强制运行）先把同一个同步以试运行方式跑一遍，只读、不写，得到会删除多少个文件。预检的 rclone 日志被丢弃，只有一行摘要写进运行的日志。源里一个文件都没有而要删除目标时，运行以 `engine.ErrEmptySource` 失败；会删除目标一半以上（且至少 10 个）时，以 `engine.ErrLargeDelete` 失败。两种失败都不改动任何文件，以 `engine.StoppedSync` 返回会删除的文件数和前 100 个文件的路径（预检时用 rclone 的 `operations.WithLogger` 收集）；`service` 把它们存进这次运行的 `run_logs` 行（`deletes`、`deletes_total`），历史详情列出这些文件，等人看过、确认后用「仍然运行」（`Job.Force`）再跑。预检的删除数同时作为真正运行的 `MaxDelete` 上限：预检没有删除时上限就是 0，源在两次之间变化也不会删掉一个没预演到的文件。copy 没有删除，不做预检。
   - **回收站**：任务的实际保留天数（`Task.Trash`）不为 0 时，运行（不是试运行，copy 和 sync 都是）把 sync 删除的文件、以及 copy 和 sync 覆盖掉的旧版本移进目标里的 `.cloudshuttle-trash/<开始时间>/`（`engine.TrashFolder`，如 `2026-11-05 14.30.12`，不含 SMB 不接受的冒号），保持原来的相对路径，而不是删掉。它就是 rclone 的 backup dir：rclone 按名字从它的远端缓存里取 backup dir，引擎用 `cache.Put` 以运行 ID 为名放进在内存中建好的远端，不写配置。回收站的远端包一层（`trashFs`）提供服务器端移动：本机和 SMB 用后端自己的移动，S3 没有移动，就在服务器端复制再删除原件；否则 rclone 会把复制记成一次传输、原件记成又一次删除，运行的数字不再说明它做了什么，`MaxDelete` 也会拦下它。每次移动 rclone 都记一次检查，引擎从检查数里减掉。回收站的远端先列一次，让 S3 后端知道存储桶已经在，不去创建它。每次运行（包括 copy）在两端都排除 `/.cloudshuttle-trash/**`：sync 不会删掉回收站，以另一个任务的目标为来源时也不会把它带走。用回收站的运行结束后（取消的除外），按文件夹名删除早于这个任务保留天数的运行文件夹，名字不是这种格式的文件夹不动；清理用独立的统计组、不计入运行的删除数，rclone 的日志静音，只写一行摘要。回收站关闭时直接删除和覆盖，已有的回收站留在原处，也不再清理。
   - **排除规则**：引擎为每次运行建一个过滤器（`engine.withFilter`，`filter.ReplaceConfig`，不碰全局配置）：先是回收站，再是任务的每条规则和全局规则（`Settings.ExcludeFor`：`ExcludeEnabled` 默认开启，把 `Settings.GlobalExcludes` 加在任务规则之后，两边都有的规则不重复），最后是大小上限（rclone 的 `MaxSize`）。规则是相对来源和目标的 glob：只有以 `/` 开头的从顶层算起，其他规则（包括含 `/` 但不以其开头的路径）都在任意层级匹配；以 `/` 结尾的表示文件夹及其中的一切（`engine.ExcludeRule` 转成 rclone 的 `- 规则**`）。过滤器作用于两端，所以 sync 既不复制、也不删除目标里被排除的文件（不用 `--delete-excluded`），删除预检和预演也按同样的过滤器计数。domain 只检查条数、长度和大小上限，规则是不是合法的 glob 由引擎判断（`engine.ValidExclude`），`service.validTask` 不合法时返回 `FieldExclude`。
   - 预检之后才调用 rclone 的 `sync.CopyDir` 或 `sync.Sync`。每次运行使用独立的统计组，每秒两次上报进度；结束时关闭后端的连接池。
   - 两端都不是本机时（例如两台 NAS），文件经本机中转，没有服务器端复制。SMB 没有哈希，靠大小和修改时间（精度 1 毫秒）判断文件是否变化。
   - 运行保留 rclone 的默认重试，可以等休眠的 NAS 唤醒；连接测试和列出文件夹只试一次，连接超时 10 秒，让人尽快看到结果。
   - 预检意味着一次 sync 会把两端各列一遍清单两次：拿安全换时间，大型任务第一次同步会慢一些。
4. 结果写回记录：`success`；`failed`，附 rclone 的错误；`canceled`，用户停止或应用退出。被删除预检拦下的运行记为 `failed`，并在 `problem` 列记下原因（`emptySource`、`largeDelete`），界面用用户的语言解释、通知也用同样的说明，原始错误留在 `message` 和日志里。写入运行日志和结果各重试三次（数据库可能正被界面读取），失败会写进应用日志文件。进程崩溃时残留的 `running` 记录，在同类进程下次启动、或另一个进程发现它已不在时改为 `canceled`。

运行 goroutine 有 panic 兜底：panic 记为 `failed`，堆栈写进应用日志，运行从“进行中”里移除，应用不退出。

## 定时任务

计划（`domain.Schedule`）按人的说法表示，不用 cron：手动；每 N 小时（N 整除 24：1、2、3、4、6、8、12，从零点起算）；每天某个时刻；每周选定的几天的某个时刻；每月某日的某个时刻（没有这一天的月份在最后一天运行）。按本机时区计算，时钟拨快跳过的时刻在跳过之后运行，不会提前。数据库里存为 JSON（`{"repeat":"weekly","time":"21:00","days":[1,4]}`），`schedule_since` 记计划设成现在这样的时间。

**界面**：任务对话框用分段控件选「手动 / 每小时 / 每天 / 每周 / 每月」，再按需选间隔、星期（按用户所在地区一周的第一天排列）、几号和时间（`ui.TimeInput`，跟随系统的 12/24 小时制）。每种方式各自记住选过的值，来回切换不丢。下方写出下次运行时间和由谁运行（系统，或只在云梭打开时）；每月 29–31 日注明短月份在最后一天运行。任务列表用一句话显示计划（「每天 21:00」「每周一、周四 21:30」「工作日 09:00」「每月 1 日 03:00」）和下次运行时间。

**到期**：任务上次开始运行（试运行不算，失败、取消都算）持久化在 `schedule_starts`，与 `schedule_since` 两者中较晚的那个之后，计划的第一个时刻已经到了，任务就到期。错过几次也只补跑一次；计划刚设好时已经过去的时刻不算错过，所以保存新计划不会立刻跑一次。`runs` 的插入触发器在同一事务中更新 `schedule_starts`，删除或裁剪历史不会改变去重状态；升级时从已有历史回填，配置备份保留此状态，恢复时与本机状态取较晚值。

**先征得同意**：登记后台项目前要用户同意，记在设置的 `background`（`domain.Consent`：未询问、同意、拒绝）。未同意时窗口不登记（已登记的会撤回，`Register(nil)`），状态为 `BackgroundOff`，由窗口自己运行定时任务。有系统调度器（`Service.SystemScheduler`）且尚未询问时，任务对话框里计划的说明写「保存后将询问…」；保存了带计划的任务后，对话框换成询问：说明会在「登录项与扩展」中添加后台项目，以及「仅在运行时执行」意味着什么，按钮为「仅在运行时执行」和「允许」（`Service.AllowBackground`）。关掉对话框不算回答，下次保存定时任务时再问。设置页「定时任务」卡片的开关可随时更改，被系统拒绝时在那里也有说明和打开「登录项」设置的按钮。这个回答属于这台电脑：恢复备份时保留本机的值；升级前已有定时任务的数据库视为已同意（它们已经由系统运行，macOS 当时已提示）。

**由系统启动**：同意之后，窗口把所有计划需要的唤醒时刻（`Schedule.Wakes`，即 launchd `StartCalendarInterval` 的写法，去重后排序）交给 `service.Registrar`：

- macOS 上是 `internal/launchagent`：写 `~/Library/LaunchAgents/<应用标识>.scheduler.plist` 并用 `launchctl bootstrap gui/<uid>` 载入。`ProgramArguments` 是应用自己的可执行文件加 `--scheduler`；`RunAtLoad` 让它在用户登录时（以及每次重新载入时）也启动一次，补上关机期间错过的；`AssociatedBundleIdentifiers` 让它在「系统设置 > 通用 > 登录项与扩展」里归在云梭名下。睡眠中错过的时刻由 launchd 在醒来后合并成一次。每月 29–31 日没有对应的日历写法，从 28 日起每天唤醒，由调度进程判断这个月是哪一天；多出的唤醒什么也不做。内容没变且已载入时不动；没有定时任务时卸载并删除。应用不在 `.app` 包里运行时（如 `go run`）不登记，因为 launch agent 会比那次构建活得久。
- 窗口在调度进程运行期间不重新登记：launchd 重新载入会先结束正在运行的调度进程，连同它的运行。改动等调度进程退出后再登记（窗口每秒检查一次）。
- 没有系统调度器时（Windows、Linux：`errors.ErrUnsupported`，`BackgroundApp`），或用户在系统设置里不允许云梭在后台运行时（`bootstrap` 失败，或载入后不在 launchd 里：`BackgroundBlocked`），窗口自己每 30 秒启动到期的任务，只在应用打开时运行；关闭窗口只是隐藏，不影响。被拒绝时，任务对话框和任务页说明原因并给出打开「登录项」设置的按钮，窗口每分钟重试登记一次，用户允许后自动恢复。这条路径上定时运行因目标被另一个任务占用而没能开始时，`OnRefused` 让界面发一条系统通知（运行记录不会多出来，因为什么都没开始）；任务本身还在运行、或这个时刻已经跑过，则什么也不做，那是正常的。

**调度进程**（`cmd/cloudshuttle` 的 `runScheduler` → `Service.RunDue`）：不调用 `mygo.App.Run`，没有窗口、不进程序坞，也不登记为应用实例，用户打开云梭时启动的仍是窗口。它打开同一个数据库、应用日志（行带 `process=scheduler`）和钥匙串条目，依次运行到期的任务、等每个结束，再看有没有新到期的；下一个到期时刻在 90 秒内就等它（系统可能略早启动它），否则退出。同一时间只有一个调度进程（`scheduler.lock`）。收到 SIGTERM（launchd 卸载它）时主动取消当前运行（包括排队中的运行），限时等待结果记录。退出等待超时时保留进程锁，直到系统在进程结束时释放。

**两个进程共用数据库**：

- 每条运行记录它属于哪个进程（`runs.owner`：`app` 或 `scheduler`）。每个进程活着时持有自己的文件锁（数据目录下的 `app.lock`、`scheduler.lock`；进程无论怎样结束，系统都会释放），另一个进程据此判断这些 `running` 记录是否真的在运行。清理时持有对方的锁直到数据库更新结束，所以拿自己的锁时会重试约两秒。锁检查出错视为状态未知，不据此清理；启动时清理本 owner 的旧记录，运行期间只清理已确认死亡的另一个 owner。获取自身进程锁失败时禁止运行。
- 开始运行和「这个任务是不是已经在运行、这个时刻是不是已经跑过」由同一条 SQL 检查活动记录和 `schedule_starts`（`store.StartRun`），两个进程同时要跑同一个任务时只会跑一次；在窗口里手动运行一个正在后台运行的任务会得到「已在运行」，删除它也被拒绝。
- 任务启动和配置恢复共用 `maintenance.lock` 与进程内互斥。恢复持锁后重新检查活动状态，数据库事务再检查全部 `running` 记录，因此不依赖窗口轮询缓存。
- 传输在进程之间轮流：在进程内的队列之后，还要拿到 `transfer.lock` 才开始，锁被占用就继续「等待运行」；打开或获取锁出错则运行失败，绝不绕过互斥。
- 调度进程每秒把运行的进度、速度和是否在排队写进它的记录，每两秒写一次到目前为止的日志；窗口每秒查一次 `PRAGMA data_version`（只有别的连接提交了改动才会变），变了就重读进行中的运行：有运行出现或结束时整体刷新，只是进度变了就只刷新进度，结束的运行交给灵动岛。窗口里的「停止」对后台的运行写 `cancel_requested`，调度进程在下一次写进度时读到并取消它。
- 失败通知由窗口发（设置里关掉时不发）：窗口自己的运行直接通知；调度进程把失败的记录标上 `notify`，窗口看到时通知一次，超过 24 小时的不再通知。窗口没有在运行时，调度进程用 `open -g … --args --wake` 在后台打开应用：`--wake` 说明这不是用户自己打开应用，主窗口保持隐藏（程序坞图标开着时也一样），应用启动时发出通知并留在它的图标处（程序坞或菜单栏，见设置）。
- 长期没有成功的提醒由窗口显示，设置里可以关掉或改天数：窗口每 6 小时完整检查一次有计划的任务，并每分钟看一次调度进程留下的 pending；最后一次真实成功（试运行不算）早于设置的天数，或从未成功且计划已经设置了这些天，就发一条通知。从未成功过的任务从计划设置的时间算起，避免刚建的任务立刻提醒。调度进程结束时也做同样的检查；它没有窗口，于是把通知记成 pending 并唤醒应用，窗口启动或下一次检查时显示。提醒记在 `stale_notices` 表，同一任务一天内不会重复，应用重启也一样；任务成功后会清除。成功时间还记在 `tasks.last_success_at`，不受运行历史保留期限影响。

## 查找局域网中的服务器

`internal/discovery` 是一个纯 Go 的小型 mDNS 客户端，只用 `golang.org/x/net` 的 `dnsmessage` 和 `ipv4`：

1. 从一个随机端口向 `224.0.0.251:5353` 组播查询 `_smb._tcp.local.` 的 PTR 记录，每个可组播的 IPv4 网卡各发一次。端口不是 5353，不和系统的 mDNSResponder 抢端口，响应方按 RFC 6762 第 6.7 节直接单播回复。
2. 收集回复中的 PTR、SRV 和 A 记录；0.7 秒和 1.4 秒时，为还缺 SRV 的实例和还缺地址的主机补发查询。
3. `service.FindServers` 一共等 3 秒，去掉本机自己的地址，按名称排序。主机名（如 `nas.local`）能在 1 秒内被本机解析到同一地址时填主机名，地址变化后仍然有效；否则填 IPv4 地址。Windows 和 Linux 上纯 Go 的解析器不解析 `.local`，会填地址。

只找得到开启了 Bonjour 的服务器，不支持 IPv6 和 NetBIOS。界面在第一次切换到 SMB 时自动查找，找到的服务器列在一个单选列表里（名称和地址，最多显示 3 行，更多时在列表内滚动，因为对话框本身不滚动）；列表下方注明这些服务器来自局域网广播、未经验证，登录前要确认是自己的设备。点选或用方向键选中一行，填好主机、端口，名称为空时一并填上；主机与某一行相同时，那一行显示为选中。`service.Options.Browse` 可以替换查找函数，界面测试用它模拟结果。

## 密钥

`service` 把 `Secrets` 包一层内存缓存（`service/secrets.go`）：每个密钥在应用运行期间只从系统凭据存储读一次。macOS 钥匙串在签名变了的应用读取它之前存的密钥时会询问用户，读取会一直阻塞到用户回答；`Service.Start` 因此在后台先读出定时任务所用存储的密钥，让询问出现在打开应用时，而不是无人值守的定时运行里。缓存只在内存中，不写入数据库或日志；钥匙串里的密钥在应用运行期间被外部删除时，要到下次启动才会发现。

后台调度进程是同一个已签名的可执行文件，钥匙串把它当作同一个应用：用户在窗口启动时的询问里选「始终允许」后，调度进程读同一个密钥也不会再被询问，无人值守的定时运行不会卡在询问上。

签名决定钥匙串认不认得应用：临时签名的身份是二进制的哈希，每次打包都变；用证书签名（`mygo.json` 的 `macos.signingIdentity`）的身份是应用标识加证书，重新打包和更新都不变。调试和发布是同一个应用：不用 `mygo dev`，它会给标识加 `.dev`，数据和钥匙串条目都与正式包分开。

## 运行日志

每次运行都有一份日志，在历史详情里显示，可以整份复制。每行一条记录：时间、级别、来源、原文，例如 `12:08:15.123 INFO   rclone  photos/a.jpg: Copied (new) size=5`。日志是技术原文，不翻译。

- **来源 `app`**：`service` 写开头（任务、方式、触发方式、是否试运行）、解析两端时的错误（例如钥匙串里没有密钥）和结束状态；`engine` 写 rclone 版本、两端的位置（不含密码）、实际打开的远端、本次生效的排除规则（条数和模式）与大小上限、复制还是同步，以及最后的统计和原始错误。
- **来源 `rclone`**：`engine/log.go` 用 `fs.SetLogger` 接管 rclone 的日志，并在启动时把 rclone 的全局日志级别设为 INFO（逐个文件的「Copied」「Deleted」等），DEBUG 不保留。rclone 打日志时不带 context，也不说明是哪次运行的；因为同一时间只有一个任务在传输，每条日志只交给它（`Job.Log`），日志因此属于这次运行。连接测试和浏览文件夹恰好与某次运行重叠时，它们的日志仍可能落进那次运行的日志（`Shared`/`rclone*` 的标记保留作兜底）。没有任务在跑时（例如测试连接、浏览文件夹）的 rclone 日志直接丢弃。删除预检期间 rclone 的日志全部丢弃（`muteRclone`），不写进任何运行的日志。
- 运行中的日志在内存里（`service.runLog`），历史详情随进度刷新，并停在最新一行；界面只在日志新增了行（`runLog.Live` 的行数变了）时重新分行，不整份重读；运行结束时先写入 `run_logs` 表，再把运行标为结束。每次运行最多保留 1 MB，之后的行只计数，并在末尾注明。`run_logs` 和 `runs` 分开存放，列历史时不读日志；早于这个功能的运行没有日志，界面会说明。
- 后台调度进程的运行，日志在运行期间每两秒写进 `run_logs` 一次，窗口的历史详情读它显示；结束时写入完整的一份。
- 应用自己的日志（`slog`）写到数据目录下的 `cloudshuttle.log`，窗口和调度进程追加到同一个文件，调度进程的行带 `process=scheduler`（同时写 stderr，超过 5 MB 时把旧文件改名为 `.log.1`）：记录运行结果没能写进数据库、退出时仍在运行的任务、定时任务失败这类窗口里看不见的问题。日志里不含密钥。

## 连接错误

`engine` 把连接失败归成三类：连不上（网络错误、DNS、超时）、认证失败（NTSTATUS `LOGON_FAILURE`、`ACCESS_DENIED`、`ACCOUNT_LOCKED_OUT`）、共享不存在（`BAD_NETWORK_NAME`），包装在 `engine.ErrUnreachable` 等错误里并保留 rclone 的原始错误。`service` 把它们换成 `domain.ErrUnreachable`、`ErrAuthFailed`、`ErrShareNotFound`，界面在连接测试和文件夹浏览器中据此显示对应的文案。运行历史里的失败消息仍是 rclone 的原文，作为技术细节显示。

## 设置

应用**没有供人使用的命令行参数或命令**：`cmd/cloudshuttle` 默认以状态栏模式运行，主窗口隐藏，macOS 的激活策略由设置里的「应用图标」决定（默认只在菜单栏，没有 Dock 图标）；只有系统会传内部参数：`--scheduler` 启动后台调度进程，`--wake` 表示它是在后台打开应用（发送失败通知、检查长期没有成功的任务），主窗口不显示。`go tool mygo ...` 是开发命令、不随应用发布；rclone 作为库使用，不解析 rclone 的命令行参数，也不读 `rclone.conf`。所有用户可调的参数都在设置页：

- **更新**：当前版本和更新进度，「自动检查更新」（默认开）和「自动下载并安装更新」（默认关），见「自动更新」。两个开关和外观一样立即生效并单独保存（`Service.SetUpdates`）。
- **外观**：跟随系统、浅色或深色。选择后立即生效并单独保存（`Service.SetAppearance`），不经过页面的「保存」，也不带上页面中未保存的修改；视图通过 `Host.SetAppearance` 交给 `cmd`，由 `mygo.Theme.SetSource` 作用于所有窗口。启动时和恢复备份后按设置重新应用。
- **应用图标**（只有 macOS 显示这一项）：程序坞与菜单栏、仅程序坞、仅菜单栏。选择后立即生效并单独保存（`Service.SetAppIcon`），同样不经过页面的「保存」；视图通过 `Host.SetAppIcon` 交给 `cmd`，由它切换激活策略（普通 / accessory）和状态栏图标（`mygo.NewTray` / `Tray.Destroy`）。关闭窗口时隐藏主窗口；「程序坞与菜单栏」模式还临时切为 accessory，移除程序坞图标并保留菜单栏，重新打开主窗口前恢复普通激活策略和程序坞图标，不改写保存的模式。「仅程序坞」关闭后保留程序坞图标，「仅菜单栏」保留菜单栏图标。默认仅菜单栏，与升级前一致；其他系统没有程序坞，始终保留通知区域图标。
- **传输**：同时传输的文件数（1–16）、同时检查的文件数（1–32）、失败操作的重试次数（1–10）、速度上限（不限 / 1 / 5 / 10 / 50 MB/s）。这些在运行开始时取一次，保存后开始的运行生效。
- **回收站**：运行删除和覆盖掉的文件在目标的回收站里保留多久（关闭 / 7 / 30 / 90 天，见「任务如何运行」），用于跟随设置的任务。保存后开始的运行生效。
- **排除**：全局规则的开关（默认开启）和清单，保存后开始的运行生效。清单是 `Settings.GlobalExcludes`，新数据库以 `domain.DevDependencyExcludes` 开头，按任何层级的同名文件夹匹配：`node_modules/`、`target/`、`.venv/`、`__pycache__/`、`.gradle/`、`Pods/`、`.dart_tool/`、`deps/`、`.terraform/` 等（见「任务如何运行」）。卡片里有一行写出规则条数，「编辑…」打开与任务对话框同样的编辑页：每行一条 glob，边输入边检查第几行不合法，可以「恢复默认」回到内置清单；保存时 `service` 去掉空行和重复、检查每条规则是合法的 glob，不合法时返回 `FieldGlobalExclude`。任务自己的排除规则照常生效，关闭全局开关后任务规则仍然排除。
- **通知**：运行失败、定时运行没能开始时是否发系统通知；定时任务连续 N 天没有成功时也提醒（3 / 7 / 14 / 30 天，默认 7 天）。只针对按计划运行的任务，试运行不算成功；从未成功过的任务从计划设置的时间算起。
- **历史**：运行记录和日志保留多久（永久 / 30 / 90 / 180 / 365 天）；保存后立即清理一次，之后每次启动清理。
- **定时任务**：云梭关闭时是否由系统运行定时任务（只在有系统调度器时显示，见「先征得同意」）。
- **备份**：是否把配置备份到 iCloud Drive（只有 macOS 显示这一项，见下节）。

设置存在数据库的 `settings` 表（一行），默认值是 rclone 自己的并发默认值、回收站保留 30 天（升级的数据库也是，已有的任务都跟随设置）、通知开启、保留 90 天、备份关闭、后台运行未询问、外观跟随系统、应用图标只在菜单栏、自动检查更新但不自动安装、全局排除开启、长期没有成功时提醒开启（7 天）；外观、应用图标和更新的两个开关随备份恢复，后台运行的同意属于本机，不随备份恢复；删除保护不是设置项，不能通过设置放开（只能对单次运行用「仍然运行」）。

## 自动更新

新版本发布在 GitHub Release（`mygo.json` 的 `updates.github`）。下载、校验签名和替换 `.app` 都由 MyGo 的 `mygo.Updater` 完成：每个平台一份清单 `update-<平台>.json`，归档和增量包用 Ed25519 私钥签名，应用内置公钥（`updates.publicKey`），签名不对就不装。没有 `updates` 配置的构建、不在 `.app` 包里运行、或所在位置不可写时，`Updater.Enabled()` 为假，设置页说明原因并给出下载页链接，不检查也不显示开关。

`internal/updates` 决定什么时候做（`cmd` 用 `mygoUpdates` 把 `mygo.Updater` 交给它，测试用假的）：

- **检查**：只在窗口进程里，调度进程不检查。打开「自动检查更新」时，启动 10 秒后检查一次，之后每天一次；状态栏、应用菜单的「检查更新…」和设置页的按钮随时检查。已经装好一个版本时不再检查，下一个版本等重启后再查。
- **找到新版本**：自动检查找到、且不自动安装时，每个版本发一次系统通知，点击打开设置页；状态栏的更新项换成「安装更新 <版本>」。后台检查失败（例如离线）不改掉已经找到的版本，只写日志；用户自己点的检查失败时在设置页说明。
- **下载**：用户点「下载并安装」，或打开了「自动下载并安装」时由自动检查直接下载。设置页显示进度条。下载完 MyGo 先把新包放在应用旁边，起一个 shell 等应用退出后换上：所以装好后无论重启还是退出再打开，都是新版本。
- **重启要等任务结束**：用户要求重启（设置页的「立即重启」、状态栏的「重启以完成更新」，或下载是用户点的）时，有任务在运行就不重启，设置页显示「将在 N 个运行中的任务结束后重启」和「取消重启」；最后一个运行结束时重启。运行包括调度进程的：`Service.Active` 两边都算，`OnChange` 和 `OnRunFinished` 让更新器重新判断。自动安装的版本还要等主窗口关闭（没人在用）才自己重启，`win.OnHide` 时也重新判断。
- 重启前主窗口开着的，在数据目录写一个空文件 `show-after-update`，新版本启动时读到就删掉它并打开主窗口。
- 新版本用同一张证书签名，钥匙串照样认得，不会询问；更新是应用自己下载的，不带隔离属性，Gatekeeper 不会再要求「仍要打开」。

## iCloud 备份

打开设置里的「备份」后，应用在 iCloud Drive 中建一个自己的文件夹 `~/Library/Mobile Documents/com~apple~CloudDocs/CloudShuttle`（已存在就沿用），把配置加密后写成其中的 `cloudshuttle.backup`：

- 副本只含存储、任务、设置和调度去重状态，不含运行历史、运行日志和密钥；密钥始终只在系统凭据存储里。
- **加密**（`internal/seal`，基于 `golang.org/x/crypto`）：打开备份时必须设置备份密码（不限长度和字符，输入两次一致即可）。密码用 Argon2id 拉伸成 256 位密钥（RFC 9106 的第二推荐参数：64 MiB 内存、3 遍、4 条并行），文件用 XChaCha20-Poly1305 加密并认证，每次写入用新的随机 24 字节 nonce。文件头（魔数 `CSBACKUP`、版本、Argon2id 参数、16 字节随机盐、nonce）作为附加认证数据，改动文件的任何一个字节都打不开；密码错误和文件被改动表现相同。系统凭据存储只保存由密码拉伸出的密钥及其盐和参数（键名 `backup/key`），不保存密码本身，所以每次改动都能自动加密写入而不用再问；拉伸密钥要零点几秒，所以设置页的保存在后台进行。没有密钥时不允许打开备份；从旧版本升级、备份已开着却还没有密码时，备份暂停，设置页提示设置密码。
- 明文只短暂出现在应用数据目录下的临时文件夹里（0700/0600），从不写进 iCloud Drive；第一份加密备份写好后，删除旧版本留下的未加密 `cloudshuttle.db`。
- **恢复**：设置页「从备份恢复」选择备份文件、输入密码，`Service.RestoreBackup` 解密到应用数据目录下的临时文件，用 `store.RestoreConfig` 打开它（旧版本的备份先迁移到当前结构，更新版本的拒绝），再在一个事务里用它的存储、任务和设置替换现在的（是否允许后台运行保留本机的），并合并调度去重状态；运行历史保留，不需要重启。有任务在运行（窗口或后台调度进程）时拒绝。旧版本的未加密备份不用密码也能恢复。恢复入口先以只读方式验证应用表结构和版本，拒绝普通 SQLite 文件和非应用定义的触发器或视图；迁移后验证存储、任务（含排除规则）、设置（含全局排除规则）及真实路径的保护和重叠关系，验证失败不改动当前配置。恢复后重新登记定时任务；同一台电脑上存储的密钥还在钥匙串里，换电脑则要重新输入。
- 打开应用时写一份；此后新建、修改、删除存储或任务，以及保存设置时再写一份。同一时间只写一份：写的时候又有改动，写完再写一次，所以最后一次改动也会到达 iCloud。
- 保存设置时先让 `icloud.Folder` 确认 iCloud Drive 已开启、文件夹能建出来；不能时以 `CodeICloudUnavailable` 拒绝打开这个开关。之后写入失败（例如 iCloud Drive 被关掉）只写应用日志，开关保持开启。
- `store.BackupConfig` 用 `VACUUM INTO` 把数据库复制成一份一致的文件（运行同时进行也不受影响），再从副本里删掉 `runs` 和 `run_logs`，并用 `VACUUM` 收掉历史占用的页，所以副本只有配置的大小；`service` 读出它、加密，写成 0600 的临时文件，再在同一文件夹里改名替换上一份，所以 iCloud 里不会出现写了一半的副本。
- 应用不启用 App Sandbox，iCloud Drive 是主文件夹里的普通文件夹，不需要 iCloud 容器权限，所以 `internal/icloud` 直接定位它，不调用 `NSFileManager` 的 ubiquity 接口。其他系统不显示这一项，`icloud.Folder` 返回 `ErrUnavailable`。

## 数据库

`internal/store/schema.sql` 是当前的完整结构，新数据库直接建表；其中 `settings` 是应用自己的一行设置（传输并发、重试、带宽、回收站保留天数、通知、历史保留、后台运行的同意、iCloud 备份、全局排除规则、长期未成功提醒），`tasks.last_success_at` 记任务的最后一次真实成功，`stale_notices` 记已经提醒或等待窗口显示的长未成功提醒；打开数据库时若没有设置就写入默认值。已有的数据库按 `store.go` 中的 `migrations` 逐步升级，`PRAGMA user_version` 记录已执行的步数。修改已有的表时，同时更新 `schema.sql` 并追加一步迁移。

启动时会清理 90 天前的运行和它们的日志（进行中的运行保留），并删掉没有运行对应的日志；这是应用自己的历史，不涉及用户文件。迁移可以是 SQL，也可以是 Go 函数（第 7 步把早期版本的五段 cron 表达式换成计划：能等价表示的照原样换，`*/5 * * * *` 这类计划表示不了的换成最接近的每天一次，并写进应用日志）。`user_version` 比本版本知道的步数多，说明是更新的应用写的，直接以 `ErrNewerDatabase` 拒绝打开，不写一个字；需要升级时先用 `VACUUM INTO` 在数据库旁边留一份 `cloudshuttle.db.v<版本>.bak`，升级失败也有原库可退。数据库文件收紧到 0600、数据目录到 0700（里面有任务路径和服务器名）。`LastRuns` 同一毫秒的并列由查询的排序固定选同一条。

## 线程

界面运行在主线程。服务可以从任意 goroutine 调用，通过回调通知变化：`OnChange`（数据变化，整体重读）、`OnProgress`（只有进度变化）、`OnRunFinished`（窗口自己的、或看到的调度进程的运行结束）、`OnNotify`（要通知的失败）和 `OnStale`（长时间没有成功的定时任务）。向系统登记计划要执行 `launchctl`，在窗口的后台循环里做，不阻塞主线程。`cmd/cloudshuttle` 用 `Window.Update` 把前两个转发到主线程执行。界面发起的慢操作（连接测试、选择文件夹对话框、存储凭据的保存和删除、设置页读取备份密钥）在 goroutine 中执行，结果通过 `Host.Update` 回到主线程。

## 界面

- **启动与窗口**：默认只在菜单栏显示状态栏图标，主窗口隐藏；macOS 使用 accessory 激活策略与 `LSUIElement`。设置里的「应用图标」可以在程序坞、菜单栏或两处显示，见「设置」。还没有存储也没有任务时（`firstRun`），启动直接打开主窗口，方便第一次配置；读取失败不算空。程序坞图标开着时，用户自己打开应用也会显示主窗口；系统在后台打开应用（`--wake`）或自动安装更新后重启时不显示主窗口；双图标模式只保留菜单栏，直到重新打开主窗口再恢复程序坞图标，避免更新后让已经关闭的图标重新出现；仅程序坞模式仍保留程序坞图标，但不会把应用带到前台（`showDockIconWithoutActivation`，不经过 mygo 会激活应用的 `SetActivationPolicy`）。关闭主窗口后任务继续；双图标模式临时隐藏程序坞图标，保留状态栏；仅程序坞模式保留程序坞图标。从状态栏、保留的程序坞图标或重新打开应用可唤出主窗口（最小化的窗口会恢复），双图标模式同时恢复程序坞图标。状态栏图标创建失败时回落为只有程序坞（其他系统上则显示主窗口，因为没有别的图标可留下）；两种图标都没有时关闭窗口退出应用。
- **状态栏菜单**（`cmd/cloudshuttle/tray.go`），自上而下：
  - 任务总数和存储总数（包括尚未运行的任务），随配置变化更新；读取失败时显示不可用，不误报为零。
  - 同步状态：就绪（中性图标，不代表上次运行成功），或运行中、等待运行的任务数（包含调度进程），为 0 的一项不写。
  - 最多 5 个活动任务，传输优先、其后是排队，下一行是进度百分比（按用户的地区格式）、已传输量和速度；总量未知时只写已传输量和速度，尚未开始传输时写正在检查文件。
  - 最近任务：从最近 200 条运行中按任务去重，列出最多 5 个非活动任务的最近结果，下一行是开始时间、传输量和耗时，试运行另有标记。
  - 更新项：平时是「检查更新…」，找到新版本时是「安装更新 <版本>」，装好后是「重启以完成更新」；点击打开设置页并做这一步（见「自动更新」）。
  - 打开主窗口和退出（中文只显示「退出」）。点击任务打开它在历史中的详情。
- 菜单的连接符（名称与状态之间、详情各部分之间）和数量都来自文案目录，跟随语言。任务名按显示宽度截断：一个中日韩文字算两个拉丁字母宽。
- 菜单项保持稳定，进度更新只改文字和图标；活动或最近任务出现、消失时才重建菜单。数据变化时窗口读一次，菜单与窗口共用这份数据（`view.Snapshot`）。图标是共用的 Tabler 线性图标，转换为原生菜单的模板图像，跟随系统明暗和选中状态着色；状态仍配文字。

- 窗口隐藏系统标题栏：侧边栏透出系统的 Sidebar 材质，红绿灯按钮在侧边栏顶部；每页的标题行就是标题栏，可拖动窗口。
- 侧边栏切换五个页面：总览、任务、存储、历史、设置。表单使用模态对话框，删除前用提示框确认。
- 总览回答「备份是否正常」，健康的数据用弱色，颜色只留给需要处理的问题。从上到下：一张卡片里的四个统计格（任务、存储、最近 7 天运行、上次运行失败的任务），数值不为 0 时是按钮，分别打开任务页、存储页、历史页（7 天内有失败时只看失败）、只看失败的历史；正在运行的卡片打开历史中这次运行的详情和实时日志，旁边的按钮停止它；最近 7 天的柱状图按自然日统计（`App.lastDays`，统计格的 7 天数字也读它，两处一致），失败的部分叠在柱顶用危险色，每天的次数在提示里（历史还不能按日期筛选，所以柱子不是按钮）；任务每个一行，点行打开这个任务的历史，右侧按钮运行它；最近运行把同一任务连续的成功折叠成一行（`App.recentGroups`），显示次数和时间范围，折叠行点开这个任务的历史，单行点开那次运行；折叠行以其中最早的运行为键，新的成功加入时这一行不会重新滑入。跳到历史时会重设筛选条件并选中、滚动到对应记录（`App.openHistory`）。
- 同一时间只有一个任务在传输，其余排队：任务列表的「最近运行」和总览的运行卡片对排队中的运行显示「等待运行」，灵动岛优先显示正在传输的那个。
- 历史一次最多读 200 条（`store.DefaultRunLimit`），读满时在列表下方注明只显示最近的；更早的记录仍在数据库里。
- 历史可以多选：每行最前面有勾选框，勾一行加一行、不影响其他已选；筛选器右侧的「全选」勾选当前显示的全部记录，全部选中时再点则全不选（部分选中时显示为未勾选，并对读屏软件标为部分选中）。也可以用单击、Cmd 点击加减、Shift 点击连选、Cmd+A 全选。选中一条时下方显示详情，多条时显示数量。删除运行记录可以用标题栏的按钮、右键菜单或 Delete、Backspace、Cmd+Backspace，先在界面里确认；记录和它的日志一起删除（`store.DeleteRuns`，一个事务），正在运行的记录保留。只删除列表里看得到的已选记录：筛选或删除后，看不到的记录不再算作已选。
- 任务对话框的「回收站」选择跟随设置（选项里写出设置的天数或关闭）、关闭，或 7 / 30 / 90 天，下方说明这个任务删除或替换的文件是否保留。
- 任务对话框的「排除」一行写出摘要（几条规则，以及大于多少的文件），「编辑…」在对话框里换出排除编辑页（和文件夹浏览器一样不叠对话框）：常用预设（`domain.ExcludePresets`）的勾选框、每行一条的其他规则、跳过大文件的选择（不限 / 100 MB / 1 GB / 4 GB / 10 GB）。规则边输入边经 `Service.ValidExclude` 检查，不合法时写出第几行；对话框的摘要下也提示有规则无效。
- 运行详情列出统计；运行把文件移进了回收站时，写出回收站文件夹（相对于目标）和文件数。被删除预检拦下的运行列出会删除的文件（最多 100 个，超过 8 个时在固定高度的列表里滚动，更多的只写数量），下面是「仍然运行…」，与任务菜单里的同一个确认；回收站开着时，确认里说明被删除的文件会移进回收站、保留几天。任务已删除或不再是 sync 时不显示这个按钮。
- 存储列表的「状态」列显示每个存储最近一次测试连接的结果：可用、失败（悬停看原因）、未测试或测试中，都是图标加文字。结果由 `service.CheckStorage` 记在 `storages` 表里（`domain.Check`：时间、是否成功、问题代码和原始错误），列表里的「测试」和保存后自动进行的测试都会更新它；编辑时改了连接方式或密码就清空，只改名称则保留。
- S3 Endpoint 拒绝 URL userinfo、查询参数和片段；引擎也拒绝旧记录中的此类地址，且日志描述移除这些字段。
- S3 的 Endpoint 用 `http://` 时，对话框在地址下面提示密钥和文件会明文传输，存储列表的地址旁也有一个警告图标；只是警告，不阻止保存（自建 MinIO 常用 http）。SMB 的「测试连接」登录服务器并列出共享，能列出就说明地址和账号可用。
- 任务的某一端是存储时，路径旁的「浏览…」在任务对话框里换出一个文件夹浏览器（对话框不叠对话框）：顶部的路径可以点回上层，列表双击或回车进入文件夹，按钮选择选中的文件夹或当前文件夹。SMB 服务器的顶层列出它的共享，在顶层必须选中一个共享才能确定。服务器回答「有哪些共享」和「打开共享」用的是两份数据：NAS 改共享名后，可能还会按旧名列出一阵，打开时却回答没有这个共享。所以 `engine.Folders` 在顶层把列出的每个共享都打开一次（最多 4 个同时，每个最多 3 秒，整轮最多 6 秒），只留下打得开的；没来得及探测的共享保留，打开时再报错；顶层还有一个共享名输入框，用来打开列表里暂时还没有的共享。打开时路径里的共享已不存在（例如在 NAS 上改了名），回到顶层并说明原因，请用户重选。文件夹由 `service.Folders` → `engine.Folders` 在后台列出，按目录打开远端（路径末尾加 `/`），免得 S3 把不存在的前缀当成文件去查。打开时从已填的路径开始，不存在就逐级退回上层；S3 没有真正的文件夹，不存在的前缀列出来是空的，停在那一层。
- macOS 访问局域网需要用户授权：`mygo.json` 的 `macos.infoPlist` 写入英文的 `NSLocalNetworkUsageDescription`，中文版在 `resources/darwin/zh-Hans.lproj/InfoPlist.strings`。
- 动效只回应变化：切换页面时新页面淡入上移；运行记录和运行卡片进出场时展开或收起；统计数字计数到新值；进度条在引擎两次上报之间平滑过渡；运行中的状态图标旋转。动效使用 mygo 的 transition 和 spring，系统开启「减少动态效果」时直接到位。
- 颜色、尺寸和圆角取自 MyGo 主题，跟随系统的亮暗模式和强调色。状态用图标加文字表示，不只靠颜色区分。
- 图标是 Tabler outline SVG，原样复制在 `internal/icons/svg`。
- 所有面向用户的文字都写在 `locales/en.json`（源语言）和 `locales/zh-Hans.json` 中；`go tool mygo generate` 生成 `locales/catalog_gen.go`，`go tool mygo i18n check` 检查缺失的翻译。

macOS 没有灵动岛接口。`internal/island` 在主屏幕顶部正中画一个与摄像头刘海同色的黑色胶囊，看起来像是从刘海里长出来的：

- 有任务运行时收起成紧凑态：左边旋转图标，刘海右边显示完成百分比；多个任务同时运行时显示「+N」。

- 尺寸变化用略带回弹的 spring 动画。

`cmd/cloudshuttle/island_darwin.go` 为它建一个无边框、透明、不抢焦点、忽略鼠标的 Panel 窗口，通过 purego 调用 AppKit：用 `NSScreen.safeAreaInsets` 和 `auxiliaryTopLeftArea`、`auxiliaryTopRightArea` 量出刘海宽度和菜单栏高度，把窗口层级设为状态栏级别（盖在菜单栏上），并替换窗口所属类（KVO 之下的原始类）的 `constrainFrameRect:toScreen:`：胶囊窗口原样返回位置，其他窗口交给原来的实现——否则 AppKit 在显示窗口、设置位置、睡眠唤醒和显示器变化后重新摆放窗口时，都会把盖住菜单栏的窗口挪到菜单栏下方。不能改窗口实例的类：AppKit 用 KVO 观察这个窗口，换类会让它释放时抛出异常、应用退出时崩溃。窗口在显示后、显示器变化时和有任务开始运行时用 `setFrame:display:` 摆到屏幕顶边；并让它出现在所有桌面空间和全屏应用旁。没有刘海的屏幕上胶囊居中显示在菜单栏里。显示器变化时重新测量。其他系统上 `island_other.go` 什么也不做。

## 测试

- `internal/domain`、`internal/store`：校验和持久化，包括从旧版数据库迁移；备份副本含存储、任务、设置和调度去重状态，不含运行历史和日志。
- `internal/icloud`：在临时文件夹上检查应用文件夹的创建、iCloud Drive 不存在和同名文件占位。
- `internal/seal`：加密后能用密码打开、错误密码、改动任一字节（头、密文、标签）都打不开、两次加密结果不同、更新版本被拒绝、钥匙串里存的密钥能照样加密。
- `internal/discovery`：用构造的回复检查记录的汇总、补发查询和过滤本机；设置 `CLOUDSHUTTLE_TEST_BROWSE=1` 后会在当前网络中实际查找一次。
- `internal/engine`：在临时目录之间做复制、同步和试运行，包括空源和“删除目标大部分”被拒绝并列出会删除的文件、强制运行放行、预检不产生文件；回收站在本机和 S3 上保留 sync 删除和覆盖掉的文件、copy 覆盖掉的文件、不多计传输和删除、不被下一次同步删除也不被复制带走，并按天数清理运行文件夹；排除规则（文件名、文件夹、从顶层算起的路径、大小上限）在两端生效，sync 不删除目标里被排除的文件，以及规则的合法性；并通过进程内的 S3 服务（`gofakes3`）往返一次；SMB 的错误分类和连不上的情况在本地测；列文件夹在本地目录和 S3 上测。rclone 没有可嵌入的 SMB 服务，设置 `CLOUDSHUTTLE_TEST_SMB=smb://user:pass@host/share` 后，会连真实服务器列出共享、在该共享里往返一次并检查错误分类，测试文件夹用完即删。
- `internal/service`：密钥存储、运行与历史记录；定时调度：到期判断（错过多次只补一次、新计划不补）、向系统登记与被拒绝时改由窗口运行、调度进程与窗口同时运行（窗口显示并停止调度进程的运行、手动运行被拒、失败由窗口通知、窗口不在时唤醒应用）、同一时间只有一个调度进程、长期没有成功的定时任务每 6 小时检查，窗口每分钟看一次 pending；调度进程结束时也会检查并留下 pending 通知、唤醒窗口；提醒按任务每天至多一次，记在 `stale_notices` 表；同步目标的保护与跨任务目标冲突、空源/大幅删除的拒绝（保存会删除的文件）与强制运行（文件进回收站）、任务的回收站跟随设置、单独关闭或自定天数、任务的排除规则规整后保存、运行时生效、不合法的规则被拒、密钥写入失败的还原；iCloud 备份在打开、启动和改动后写入，不可用时拒绝开关。
- `internal/launchagent`：生成的 plist；设置 `CLOUDSHUTTLE_TEST_LAUNCHD=<目录>` 后，会向 launchd 登记一个运行 `/usr/bin/true` 的临时任务、确认已载入，再卸载删除。
- `internal/updates`：用假的 `Source` 检查自动检查只通知一次、后台失败保留已找到的版本、有运行时重启等待、取消重启、自动安装只在安静时重启、安装失败可重试。
- `internal/view`：用 `ui.Tester` 在无窗口环境下模拟用户点击和输入，包括设置页的更新卡片（检查、安装、等任务结束后重启、不能更新的副本）、设置每周计划、计划的文字说明、系统拒绝后台运行时的提示。
- `internal/island`：用可控时钟检查胶囊的隐藏、展开、紧凑三种状态及切换时机。
